# 인스타그램 맞팔 확인기

서버 없이 파일을 분석하는 한국어 정적 앱입니다. `index.html`을 열거나 `python3 -m http.server 8000`으로 실행하세요. GitHub Pages의 `/instagram-follow-checker/` 같은 하위 경로도 지원합니다. JSZip은 `vendor/`에서 읽으며 런타임 패키지 설치가 필요 없습니다.

인스타그램 정보 다운로드에서 **팔로워 및 팔로잉**, **좋아요, 댓글, 스토리 활동, 메시지**를 선택하고 **전체 기간 · JSON**으로 받으세요. ZIP 전체 또는 개별 JSON/기존 HTML 목록을 선택할 수 있습니다. 일부 파일이 없거나 손상되면 가능한 파일만 분석합니다.

- 맞팔 비교, 검색·정렬, CSV 복사·다운로드, 기타 관계 목록을 지원합니다.
- 날짜별 스냅샷을 저장하면 계정별 등장·사라짐 구간, 재팔로우, 팔로워·팔로잉 수 변화를 보여줍니다. 날짜당 하나를 보관합니다. 구형 백업에는 팔로잉 수가 없어 해당 구간은 생략합니다.
- 목록의 태그(지인·브랜드·무시·직접 입력)와 메모는 자동 저장됩니다. 태그가 있는 계정을 숨길 수 있습니다.
- 좋아요·댓글·스토리는 **내가 한 반응**입니다. DM 순위는 **상대가 보낸 메시지 수**입니다. 표시 이름의 UTF-8/latin1 깨짐을 복구합니다. 여러 대화에서 공통으로 등장하는 발신자를 나로 추정하므로 내 표시 이름을 확인·선택하세요.
- 시간대·월별 통계는 기기 현지 시간의 좋아요·댓글·내 발신 메시지입니다. 시각이 없는 항목은 제외합니다. 스토리 활동은 이 통계에 넣지 않습니다.
- 유령 팔로워는 제공된 자료에서 반응·DM 연결이 없는 계정의 **추정**입니다. DM 표시 이름과 아이디는 다를 수 있으며, 누락된 자료·기간·그룹 대화 때문에 오차가 있습니다. 활동 자료가 없으면 비활성화합니다.
- 고정 계정 ID가 없으므로 아이디 변경 여부는 판별할 수 없습니다. 사라짐은 언팔·삭제·차단 등을 구별하지 못하며 정확한 발생 시각도 알 수 없습니다.

스냅샷·메모는 localStorage → IndexedDB → 메모리 순서로 보관합니다. 메모리만 사용 가능하면 새로고침 전에 JSON을 내보내세요. JSON 내보내기에는 태그·메모가 포함되며 기존 버전 1 백업도 가져올 수 있습니다. 가져오기는 ID **또는 날짜**가 같은 스냅샷을 중복 추가하지 않습니다. 메모 충돌은 가져온 내용을 우선합니다. 원본 활동·DM 내용은 백업과 Drive에 포함하지 않습니다. 여러 인스타그램 계정 자료는 별도 브라우저 프로필에서 관리하세요.

## Google Drive 설정

1. Google Cloud Console에서 프로젝트를 만들고 **Google Drive API**를 사용 설정합니다.
2. Google Auth Platform에서 OAuth 동의 화면(브랜딩·대상·데이터 액세스)을 설정하고 `https://www.googleapis.com/auth/drive.appdata` 범위를 추가합니다. 테스트 상태라면 사용할 Google 계정을 테스트 사용자로 추가합니다.
3. OAuth 클라이언트를 **웹 애플리케이션** 유형으로 만듭니다. 승인된 JavaScript 원본에 `http://localhost:8000`, 실제 배포 원본(예: `https://사용자명.github.io`)을 추가합니다. 원본에 `/instagram-follow-checker/` 같은 경로를 넣지 않습니다. 팝업 토큰 방식이므로 리디렉션 URL이나 클라이언트 비밀 키는 사용하지 않습니다.
4. `config.js`의 `const GOOGLE_CLIENT_ID = '';`에 클라이언트 ID를 넣습니다. ID가 비어 있으면 버튼은 **설정 필요**로 비활성화됩니다.
5. 앱의 저장/불러오기 버튼을 누르면 Google 도구를 처음 로드하고 동의를 요청합니다. 스냅샷·태그·메모를 앱 전용 `appDataFolder`의 `igfc_snapshots.json` 한 파일에 저장합니다. **저장은 원격 백업을 현재 내용으로 교체**하며, **불러오기는 기기에 병합**합니다. 기기마다 저장하기 전에 불러와 병합하세요. 토큰은 영구 저장하지 않습니다.

설정 참고: [Google 토큰 클라이언트 안내](https://developers.google.com/identity/oauth2/web/guides/use-token-model), [Drive 앱 전용 데이터 안내](https://developers.google.com/workspace/drive/api/guides/appdata).

## 오프라인·테스트

HTTPS 또는 localhost에서 서비스 워커가 앱 셸·JSZip·아이콘을 저장합니다. 최초 온라인 접속 후 오프라인에서도 파일 분석을 사용할 수 있습니다. Drive 동기화에는 인터넷이 필요합니다. 앱 셸을 변경해 배포할 때 `sw.js`의 캐시 버전도 올리세요.

Node.js 20.19 이상에서 `npm install` 후 `npm test`를 실행합니다. jsdom으로 실제 페이지를 로드하여 ZIP·구형 백업·태그·타임라인·활동·저장소 대체·Drive 모의 호출·서비스 워커를 검증합니다. 실제 Google 로그인과 브라우저의 PWA 설치 화면은 수동 확인 대상입니다.

`samples/sample_export_full.zip`과 `samples/sample_snapshot_backup_full.json`은 가상 계정만 사용한 확장 예시입니다. `npm run samples`로 다시 생성할 수 있습니다. 기존 간단한 샘플도 유지합니다.
